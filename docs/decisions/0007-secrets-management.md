# ADR 0007: Secrets management

- Status: **Proposed** (key holders open: D3)
- Date: 2026-11-16

## Decision

- No secret is ever committed in plain text.
- Server-wide secrets (PostgreSQL superuser password, restic password, S3 keys, Telegram token) are stored in **Ansible Vault** files (`*.vault.yml`) committed **encrypted**.
- Each school's `.env` is generated by Ansible on the server from vaulted values, with file mode `0600`, owned by root. It is also included in the encrypted backups.
- Every school gets its own `DJANGO_SECRET_KEY` and its own database password.
- The Vault password and restic password are kept by the owner and one named deputy (D3) in a password manager, plus a sealed paper copy. Never on the server in plain text except the restic password file needed by the backup job (mode `0600`).
- Hostinger API tokens and GitHub tokens stay on the operator's machine, never in this repository or on the server.

## Alternative considered

SOPS with age keys: good, but adds a second tool. Ansible Vault is enough while one small team operates the servers.

## Rotation

See [rotate-secrets runbook](../../runbooks/rotate-secrets.md). Rotate immediately when a person with access leaves or a leak is suspected.

## Consequences

- Losing the Vault password means re-creating server secrets; losing the restic password means the backups cannot be read. Both must be recoverable by two people.
